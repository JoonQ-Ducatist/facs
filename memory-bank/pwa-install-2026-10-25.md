# PWA 설치 안내 — 2026-10-25

상태: 로컬 구현·집중 검증 완료. 커밋·푸시·운영 배포 전. 담당 Codex. 기존 미커밋 SEO/GA4 작업은 보존했다.

## 확정한 사용자 규칙

- 화면 언어(영어/한국어)로 설치 안내를 제공한다. 최초 진입 직후 사용을 방해하지 않도록 안정된 화면에서 5초 뒤 한 번 노출한다. (사용자 요청으로 기존 8초에서 단축)
- 사용자 추가 결정: `닫기`는 **이번 방문만** 닫는다. 같은 문서 방문의 메뉴 이동·화면 전환·백그라운드 복귀·재활성화·React 재마운트로 다시 나타나지 않는다. 새 문서 방문(새로고침/새 접속)에서는 다시 노출할 수 있다.
- `오늘 하루 그만보기`는 기기 현지 날짜를 localStorage `facs_pwa_hide_day_v1`에 저장한다. 같은 날 새로 접속하거나 새 탭을 열어도 숨긴다. 다음 현지 날짜부터 새 방문에서 다시 안내한다. 24시간 고정 타이머가 아닌 ‘오늘’ 기준이다.
- 닫기 상태는 계정이 아닌 기기/방문 설정이다. 로컬 저장이 차단되어도 사이트를 막지 않고 메모리로 현재 방문의 선택을 유지한다. 저장소가 차단된 브라우저의 재접속 간 하루 숨김은 보장할 수 없다.
- 새 설치 안내는 비모달 region이다. 배경 클릭을 차단하거나 포커스를 강제로 옮기지 않는다. 하단 좌측에 오늘 숨김, 우측에 닫기를 배치한다. Escape도 이번 방문 닫기로 처리한다.
- 업로드/운영 화면, 약관 동의 화면, 인증 이메일 폼, 활성 입력/키보드, 다른 dialog, 전체화면 동영상, 백그라운드에서는 안내를 표시하지 않는다. 사용자가 닫지 않고 잠시 가린 안내만 원래 허용 화면으로 돌아오면 계속 볼 수 있다.

## 설치 흐름과 PWA 구성

- `beforeinstallprompt`를 앱 마운트 전에 보관한다. 브라우저가 설치 가능하다고 알린 경우에만 `설치` CTA를 표시하고 사용자의 클릭 안에서 실제 `prompt()`를 호출한다. 이벤트는 한 번만 사용한다.
- 네이티브 설치창 수락은 곧 설치 완료라고 보고하지 않는다. `appinstalled` 또는 standalone 실행 증거를 확인한다. 취소하면 이번 방문 안내를 닫는다. API 실패는 수동 설치 안내로 복구한다.
- iPhone/iPad에서는 자동 설치창을 가장하지 않고 **공유(또는 페이지 메뉴→공유) → 홈 화면에 추가 → 웹 앱으로 열기(표시되는 경우) → 추가**를 안내한다. 지원되는 iOS 타 브라우저에서도 공유 메뉴를 안내하며, 메뉴가 제공되지 않는 앱 내 브라우저는 Safari/Chrome으로 열도록 안내한다.
- Android 등에서는 실제 설치 이벤트가 아직 없을 때 `설치 방법 보기`로 메뉴의 ‘앱 설치/홈 화면에 추가’를 안내한다. 인앱 브라우저에서 브라우저를 자동으로 전환하거나 새 권한을 요구하지 않는다.
- 설치 확인값 `facs_pwa_installed_v1`은 이 브라우저/기기 저장소 범위에서 재안내를 억제한다. iOS의 다른 브라우저·별도 저장소·삭제 후 설치 여부를 웹이 전역 판별할 수 있다고 보장하지 않는다. 새로운 beforeinstallprompt 이벤트는 오래된 설치 확인보다 우선한다.
- 영어/한국어 manifest를 분리하고 동일 `id: /`, `scope: /`를 유지한다. 시작 주소는 `/?source=pwa`, `/ko/?source=pwa`, `display: standalone`, `orientation: any`. 현재 화면 언어에 맞게 manifest 링크도 전환한다. 한국어 정적 HTML 생성에도 반영했다.
- 서비스워커는 **network-only navigation**이다. 캐시 저장·선다운로드·미디어 프리패치·푸시 구독을 추가하지 않는다. 오프라인에서는 재연결 안내만 제공하고 실제 피드/업로드는 온라인 연결을 요구한다. API·미디어·인증 응답은 가로채지 않는다. 강제 새로고침이나 skipWaiting도 추가하지 않아 작성 중인 화면을 교체하지 않는다.
- `sw.js`/manifest 재검증 헤더를 추가했다. 기존 rewrite·배포 브랜치 규칙은 유지한다.

## 문구·반응형·아이콘

- 영어 제목: **Your next perspective. One tap away.** / 본문: **Add FACt.Smack to your Home Screen.**
- 한국어 제목: **새로운 시선, 터치 한 번이면.** / 본문: **FACt.Smack을 홈 화면에 추가하세요.**
- 세로: 좌우 12px, 최대 폭 430px, 하단 탐색 메뉴 위에 12px 여백+safe-area. 로그인 화면에서는 하단 12px+safe-area와 본문 여백을 확보한다. 내용 크기대로 표시하며 확장 안내는 최대 310px/42dvh 안에서 스크롤된다.
- 가로: 오른쪽 아래 2열 카드. 최대 폭 390px, 기존 좌측 216px 메뉴를 피하는 최소 240px 공간을 둔다. 844×390 CSS px에서 실제 DOM 카드 **390×121.5px**, x=442/y=256.5를 확인했다. 콘텐츠·버튼·하단 작은 닫기 행이 구분된다.
- 이 크기는 보편적인 ‘최적 픽셀’ 표준이 아니라 기존 FACS 메뉴와 미디어 공간에 맞춘 설계 결정이다. 작은 글자여도 닫기 버튼은 세로 40px, 가로 36px 터치 영역을 확보했다.
- 아이콘 권장: 기존 **네이비 #091a2e 바탕 + 흰색 공식 나방**. 홈 화면의 작은 크기에서 긴 서비스명을 그림에 넣지 않고 OS 아이콘 이름 `FACt.Smack`을 사용한다. 기존 192/512 PNG와 180px apple-touch-icon을 재사용했다. 현재 아이콘을 maskable로 잘못 선언하지 않았다. 별도 adaptive/maskable 안은 날개가 잘리지 않도록 여백을 둔 추가 자산으로 후속 제안할 수 있다.

## 조사 근거와 적용 판단

- [Google: PWA 설치 홍보 패턴](https://web.dev/articles/promote-install): 설치 안내가 로그인/주요 행동을 방해하지 않아야 하며 쉽게 닫을 수 있어야 한다. 이를 비모달·지연 노출·입력 중 숨김으로 반영했다.
- [Google: 맞춤 설치 경험과 Spotify 사례](https://web.dev/articles/customize-install): 실제 브라우저 설치 가능 이벤트와 사용자 클릭을 연결하는 흐름을 참고했다. Spotify의 현재 전체 UI를 직접 재현하거나 검사했다고 주장하지 않는다.
- [Twitter Lite 공식 소개](https://blog.x.com/en_au/topics/company/2017/introducing-twitter-lite): 홈 화면에서 한 번에 재진입하는 가치 설명을 참고했다. 2017년 사례이며 현재 X 화면의 최신 디자인이라고 제시하지 않는다.
- [Apple: iPhone 홈 화면 웹 앱](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios): Safari 메뉴·공유·홈 화면에 추가·웹 앱으로 열기·추가 순서를 반영했다.
- [MDN: 설치 플랫폼 지원](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Installing): iOS 16.4 이후 지원 브라우저에서도 설치할 수 있으므로 무조건 Safari만 가능하다는 오래된 단정은 사용하지 않았다.
- [Material: Bottom sheets](https://m1.material.io/components/bottom-sheets.html): 내용과 화면에 맞는 높이를 참고했다. 가로 카드는 기존 FACS 좌측 메뉴를 보존하기 위한 자체 적응형 구성이다.
- Gemini는 제한된 최신 설치 UX 조사에 한 번 사용했다. 영구 닫기·임의 설치 성공·일반화된 크기·무조건 Safari 강제 등 사용자 요구 또는 공식 근거와 다른 제안은 채택하지 않았다.

## 로컬 안내 미노출 후속 점검

후속 변경: 사용자가 피드·랭킹·프로필 정상 노출을 확인한 뒤 안내 대기 시간을 5초로 단축했다. 로컬 진단 문구도 5초로 변경했다. 업로드 화면 제외 및 기존 방문 닫기·당일 숨김 규칙은 유지한다. 집중 확인은 타이머/문구 일치와 화면 허용 목록 유지 2개이며 전체 테스트·빌드·배포는 실행하지 않는다.

- 사용자 환경: Mac Chrome 로컬 주소, 모바일 화면 전환. DOM 폭 351px로 모바일 조건을 충족했다.
- 원인: 앞선 에이전트 QA에서 선택한 ‘오늘 하루 그만보기’가 동일 로컬 브라우저에 남았다. 개발 전용 `?pwaCheck=1` 진단 화면에서 실제 당일 숨김 상태를 확인했다. 노출 조건 오류로 추정해 사용자 숨김 선택을 무시하는 수정은 하지 않았다.
- 로컬 전용 진단 UI와 ‘점검용 숨김 선택 초기화’를 추가했다. 초기화는 설치 안내의 당일 숨김과 이번 방문 표시 여부만 재설정하며 인증 저장값과 설치 확인값은 보존한다. 운영 빌드에서는 진단 UI를 표시하지 않는다.
- 해당 버튼을 키보드로 실행한 뒤 로그인 미리보기에서 한국어 안내를 확인했다. 이후 일반 주소 `http://127.0.0.1:4173/ko/`에 새로 접속하여 실제 피드와 ‘새로운 시선, 터치 한 번이면.’, 설치 버튼, 오늘 하루 그만보기/닫기가 함께 표시되는 것을 확인했다. 다시 숨김을 선택하지 않고 점검 화면을 남겼다.
- 집중 테스트: `node --test --test-name-pattern='closing survives|local dismissal reset' src/services/pwaInstall.test.js` 2/2 통과. 기존 닫기 유지와 초기화 범위(인증·설치 확인 보존)를 검증했다. 전체 테스트·빌드·배포는 반복하지 않았다.
