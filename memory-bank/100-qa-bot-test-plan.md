# (100) QA bot 테스트 결과: 실행 계획

## 목적과 경계

- 목표는 실제 이용자 수가 적은 단계에서도 업로드, 평가, 스크랩, 랭킹, 실시간 반응과 반응형 화면을 반복 검증하는 것이다.
- 가상 사용자는 내부 QA 전용이다. 운영 도메인, 운영 Supabase, 실제 피드, 랭킹, 조회·평가·반응 지표에 절대 접근하거나 합산되지 않는다.
- 이 문서는 계획과 안전 기준만 기록한다. 봇 코드, 계정, 사진, 게시물, 투표, 스토리지 파일은 `main`에 넣지 않고 별도 `feat/facs-synthetic-qa` 브랜치와 로컬 Docker QA DB에만 둔다.
- 모든 테스트 레코드는 `synthetic/test` 표식을 갖고, 운영 환경 URL 또는 프로젝트 참조가 감지되면 실행을 중단한다.
- 테스트 페르소나는 성인 20~49세만 사용한다. 미성년자, 교복 콘셉트, 실존 인물, 실제 주소·장소 식별 정보는 사용하지 않는다.

## 실행 환경

| 영역 | 역할 | 데이터 수명 | 외부 노출 |
|---|---|---|---|
| 로컬 Docker | 100인 시뮬레이션과 시각 점검 | QA 종료 시 일괄 삭제 | 없음 |
| 원격 QA 브랜치 | 코드·리포트·검증 결과 보관 | 브랜치 유지 기간 | 없음 |
| 접근 제한 스테이징 | 필요 시 다기기·실시간 연결 검증 | 짧은 기간 후 삭제 | 승인된 팀만 |
| main·운영 | 실제 사용자 기능만 | 운영 정책에 따름 | 공개 |

## 인구와 활동 모델

- 100명: 한국어권 50명, 영어권 50명 / 남성 50명, 여성 50명 / 성인 20~49세.
- 각 페르소나는 사진 취향, 업로드 빈도, 평가 성향, 탐색 속도, 스크랩 성향, 접근성 필요를 다르게 가진다.
- 가상 하루마다 6개 카테고리별 최소 2개 게시물을 만든다. 게시물은 1~5개 미디어를 갖고, 권리 확보 또는 AI 생성 성인 이미지로만 구성한다.
- 이메일 인증은 사용하지 않는다. 로컬 전용 테스트 세션으로만 로그인 상태를 만들며, 실제 메일·SMS·결제·외부 API 비용을 발생시키지 않는다.

## 검증 시나리오

1. 공개 아이디 설정과 중복 확인.
2. 사진·동영상 업로드, 다중 사진 순서, 새로고침 뒤 피드 유지.
3. YES/NO와 나이 평가, 계정당 게시물 1회 제한, 자기 게시물 1회 평가.
4. 평가 완료 뒤 결과 패널에서 시작하는 Y/N/나이 풍선과 한 시간 만료.
5. 스크랩 추가·제거, 피드와 랭킹 이동, 프로필 스크롤과 로그아웃.
6. 세로·가로 모바일, PC, 한국어·영어 화면의 시각적 밀도와 터치 동선.

## (100) QA bot 테스트 결과 공간

각 실행은 `memory-bank/100-qa-bot-results/` 아래에 결과를 남긴다. 이 폴더는 QA 브랜치에만 생성한다.

| 항목 | 기록 내용 |
|---|---|
| 실행 요약 | 실행 시각, 커밋, 환경, 성공·실패 수, 삭제 여부 |
| 페르소나 리포트 | 가상 사용자, 여정, 불편, 심각도, 재현 경로 |
| 시각 증거 | 화면 크기, 전·후 캡처, 겹침·여백·가독성 관찰 |
| PM 검토 | 적용·보류·반려, 담당 영역, 다음 확인 항목 |
| 정리 보고 | 테스트 계정·게시물·평가·파일 삭제 결과 |

사용자에게 점검을 요청할 때는 `점검 항목 | 클릭 순서 | 정상 기준` 표를 사용하고, 클릭 순서는 `A → B → C` 형식으로 적는다.

## PM 승인 게이트

- 시뮬레이터 구현 시작 전: 격리 환경과 테스트 페르소나 구성 승인.
- AI 생성 테스트 이미지 사용 전: 이미지 스타일·표기 방식 승인.
- 스테이징 접근 전: 도메인·접근자·보존 기간 승인.
- 제품 수정 반영 전: QA 리포트와 재현 근거를 PM이 검토.
- QA 데이터 정리 전: 삭제 대상과 결과 확인.
