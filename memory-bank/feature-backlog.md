# FACt.Smack 전체 기능 백로그

> 기준 문서: product-philosophy.md, monetization.md, 90-day-cash-loop-plan.md, service-design-rule.md, TECH-AGENTS.md, progress.md
>
> 이 문서는 사용자 기능과 관리자 기능을 한 목록에서 관리한다. 새 기능을 발견하거나 범위가 바뀌면 이 문서를 먼저 갱신한다.

## 1. 운영 원칙과 단계 검증 게이트

각 단계는 아래 순서를 반드시 따른다.

1. 해당 단계의 범위와 완료 기준을 이 문서와 `90-day-cash-loop-plan.md`에서 확인한다.
2. 구현과 자동 검증을 수행한다.
3. 사용자에게 수동 검증을 요청하고 결과를 progress.md에 기록한다.
4. 사용자가 명시적으로 **적합**이라고 확인하면, 검증된 변경을 로컬 개발 소스에 반영한다.
5. Chrome 브라우저에서 로컬 실행 화면을 열어 반영 결과를 제공한 뒤에만 다음 단계로 진행한다.
6. 보완이 필요하면 같은 단계에서 수정·재검증을 반복한다.

- 사용자의 적합 확인 전에는 다음 단계의 기능 구현을 시작하지 않는다.
- 단계 완료 기록에는 검증 대상, 결과, 확인 날짜, 남은 위험을 포함한다.
- P1 정책이 미결정인 동안 실제 계정, 이미지 업로드, 공개 피드, 투표 API는 구현하지 않는다.
- 관리자 기능은 일반 사용자 기능과 별도 권한·라우트·감사 로그를 전제로 한다.

## 6. 유지 규칙

- 새 기능 요청은 이 백로그에서 해당 ID를 찾거나 새 ID를 추가한 뒤 계획에 반영한다.
- 사용자 기능을 새로 정의하거나 변경하면, 같은 작업에서 관리자 기능 영향을 반드시 검토한다: 설정값 관리, 대상 조회·검색, 상태 변경·제어, 운영 지표·작업 모니터링, 권한, 감사 로그.
- 위 영향 중 하나라도 필요하면 ADM 항목을 새로 만들거나 기존 항목의 범위·완료 기준을 갱신한다. 관리자 기능이 불필요한 경우에도 그 이유를 기능 기록에 남긴다.
- 기능을 구현한 뒤에는 상태를 진행 중으로, 사용자 적합 확인 후에만 완료로 바꾼다.
- 관리자 기능은 사용자 기능보다 우선해서 권한·감사·개인정보 보호 기준을 검토한다.
- P1 정책과 충돌하거나 새 외부 서비스·개인정보 흐름이 생기면 service-design-rule.md와 TECH-AGENTS.md를 함께 갱신한다.
- 완료된 정책도 운영 지표, 신고·검토 결과, 법·플랫폼 요구사항 및 사용자 피드백에 따라 계속 재검토한다. 변경이 필요하거나 개발 착수 조건이 충족되면 사용자에게 알리고, 적합 확인 후 문서와 구현을 함께 갱신한다.
