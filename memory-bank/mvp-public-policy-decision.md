| B. 약관·업로드 권리 확인 | `member_terms_acceptances`는 회원·문서 버전·언어·시각을 저장하고 `profiles` 삭제 시 cascade다. `member_rights_consents`는 회원·권리 문서 버전·시각을 저장하며 회원 참조가 restrict다. 두 기록 모두 자동 만료·파기 로직이 저장소에 없다. | 서로 다른 외래키 규칙을 `REL-05` 설계에서 해결해야 한다. 보존 필요 기간과 파기·분리 보관 기준은 운영 결정과 출시 후 법률 검토에 남긴다. 이미 구현된 동의 기록을 다시 만들지 않는다. |
| C. 실시간 반응·기기 캐시 | **운영 현행:** `post_live_reaction_events`에는 게시물 ID·반응 종류·집계값·시각이 있고 투표자 ID는 없다. RLS는 생성 후 1시간 이내의 행만 읽도록 하지만, 운영 DB에는 시간 만료 파기 작업이 없다. 게시물 삭제 시 행은 cascade된다. 브라우저의 편의 캐시는 로그아웃 경로에서 일괄 제거되지 않는다. | **로컬 후보:** 사용자 결정으로 게시 후 24시간·해당 글을 볼 수 있는 모든 로그인 회원에게 풍선을 넓히고, 생성 24시간 초과 행은 일일 파기한다. 운영 반영 전까지 1시간 조회 제한을 1시간 보존기간으로 고지하지 않는다. 오래된 행의 실제 운영 건수는 미확인이다. |
| D. 제공자 기록 | Resend Free 메일·로그 30일은 제공자 공식 안내이며, Supabase·Vercel 로그의 짧은 기간은 대시보드 조회 가능 기간이다. | 제공자 내부 삭제 시점이나 FACS가 직접 파기할 수 없는 기록에 임의의 일률 기간을 붙이지 않는다. 확인 가능한 계정 계약·설정과 출시 후 법률 검토를 분리한다. |

2026-10-18 사용자는 아래 A·B·D 원칙을 승인했고, C의 의미 설명을 검토한 뒤
실시간 반응 행 파기도 승인했다. 이어 풍선의 실시간 조건을 게시 후 24시간으로,
대상을 작성자·평가자에서 **해당 게시물을 열람할 수 있는 모든 로그인 회원**으로
확대하도록 요청했다. 비로그인 미리보기에는 전체 피드가 없으므로 포함하지 않는다.
C의 SQL은 사용자 승인 후 2026-10-18 스테이징에 적용·검증했고 앱 변경은 로컬에만
준비했다. 2026-10-18 최종 반영 승인으로 운영 SQL 2개를 적용했고, 운영 앱도
동일 승인 묶음으로 커밋·main 반영·배포한다. 적용 직전·직후 만료 풍선 이벤트는
11건으로 유지됐으며, 실제 배포 증거는 작업 완료 보고와 출시 점검표를 따른다.
기존 피드·업로드에 차단을 추가하지 않는다.

#### MVP 결정안 — A·B·C·D 승인, C 운영 DB 적용 완료·앱 운영 반영 승인

| 결정 | 권장안 | 승인 뒤에만 할 일 |
| --- | --- | --- |
| A. 계정·상호작용 — **승인** | 계정이 활성이고 서비스 제공에 필요한 동안 계정·프로필과 남은 평가·관계 기록을 유지한다. 임의의 휴면 기간을 새로 만들어 자동 삭제하지 않는다. 확인된 열람·정정·삭제·처리정지 요청은 기존 공식 메일로 개별 접수·본인 확인 후 가능한 범위와 예외를 회신한다. 계정 탈퇴 자동화는 승인대로 MVP 이후 `REL-05`에 둔다. | 새 자동 계정 파기는 만들지 않는다. 공개 문구는 ‘무기한 보존’ 또는 ‘요청 삭제 불가’로 쓰지 않는다. 실제 수동 DB 삭제 요청이 생기면 영향·법령상 예외·대상 건수를 확인하고 별도 승인받는다. |
| B. 약관·업로드 권리 증적 — **승인** | 회원이 서비스와 업로드 기능을 사용하는 동안 현재의 회원·문서 버전·시각 기록을 유지한다. 업로드 권리 확인은 게시물 단위가 아닌 회원·문서 버전 단위이므로 게시물 1건 삭제에 연동해 지우지 않는다. 회원 종료 후 증적의 보존·분리·파기는 `REL-05` 설계와 출시 후 법률 검토에서 정한다. | 이미 구현된 영수증 저장을 중복 구현하지 않는다. `member_rights_consents`의 `on delete restrict`와 약관 기록의 cascade 차이를 계정 종료 설계에서 해결한다. |
| C. 실시간 반응 행 — **원칙·범위 승인, 스테이징 적용** | 앱은 게시 후 첫 24시간의 서버 풍선에 이 행을 사용한다. DB 읽기 권한은 **각 반응 행이 생성된 뒤 24시간**으로 제한한다. 예를 들어 게시 10:00·투표 10:20이면 앱의 실시간 표시 창은 다음 날 10:00에 끝나고 해당 행의 DB 읽기 권한은 다음 날 10:20에 끝난다. 생성 24시간이 지난 행을 다음 일일 실행 때 영구 파기한다. 해당 게시물을 볼 수 있는 로그인 회원 모두가 개별 Y/N·나이 풍선을 볼 수 있지만, 미평가자의 최종 집계 결과는 계속 가린다. | `202610180001_live_reaction_retention.sql`과 앱 변경을 로컬에 준비했고 관련 계약 테스트 8개를 통과했다. 2026-10-18 스테이징 적용 직전 풍선 이벤트 2건은 모두 24시간 초과였고, 적용 직후에도 2건을 유지했다. RLS 24시간, 매일 04:00 UTC 파기 cron, 트리거·파기 함수 24시간 조건, 회원의 파기 함수 실행 불가를 확인했다. 운영 대상/삭제 건수 확인 뒤 운영 DB 적용은 별도 승인받는다. 실제 투표·게시물·최종 집계는 파기 대상이 아니다. 팔로워 공개·차단·숨김 접근 규칙이나 피드·평가·업로드의 쓰기 제한을 바꾸지 않는다. |
| D. 브라우저 편의 캐시 — **승인·로컬 준비** | 성공한 로그아웃에서 FACS의 계정별 평가·팔로우·차단·최근 반응·Boost 화면 캐시와 샘플 스크랩 캐시만 지운다. 서버의 평가·관계·콘텐츠와 사용자가 선택한 언어, GA4 쿠키는 이 변경으로 건드리지 않는다. | 로컬 코드와 국소 테스트 3개를 준비했다. 서버에 없는 샘플 팔로우·차단·스크랩은 기기 전용 선택이므로 로그아웃 뒤 복구되지 않는다는 점을 공개 안내에 명시해야 한다. 운영 배포는 별도 승인 후 한다. |

풍선의 실제 화면 계약: 본인 평가가 성공하고 즉시 집계가 반환되면 게시 시각과
무관하게 해당 피드 카드에 Y·N 또는 숫자 나이 풍선이 약 2.45초 뜬다. 집계 응답이

개별 Y/N·나이 반응은 볼 수 있으나 최종 집계는 평가 전까지 가린다. 풍선은 피드에서
해당 카드가 표시될 때만 보이며 투표자의 신원은 표시하지 않는다.
샘플 카드의 본인 즉시 풍선은 로컬 시연 경로이고 서버 실시간 반응 행의 보존·파기와
무관하다. 승인된 파기는 이 서버 풍선 연출용 행에만 적용된다.
