# 로그인 하단 소개 확장 복원 — 배포 승인

사용자가 운영 로그인 화면의 소개·FAQ 영역을 승인하지 않은 화면 변경으로 지적했다.

## 원인과 이력

- 기본 소개 2문단은 사용자 승인을 기록한 `memory-bank/production-recovery-2026-10-18.md`의 ‘승인된 소유권·홈페이지 보강’에 따라 `1647851`에서 이미 추가·배포되었다.
- `2a69b7f`의 DISC-02 작업에서 SEO/GEO 보완을 이유로 로그인 화면의 제목·본문을 확장하고 FAQ 3개와 언어 링크를 추가했다. 메타/검색 보완과 시각적 화면 확장을 구분해 별도로 확인하지 않은 것이 문제다.
- 사용자 지적에 따라 이번에 확장한 런타임 로그인 영역을 직전의 짧은 설명으로 되돌렸다. 동그라미 영역 전체가 이번 배포에서 신규 생성된 것은 아니므로 기본 설명까지 임의로 삭제하지 않았다.

## 변경과 검증 범위

- AuthEntryView의 기존 제목·본문 2문단을 복원하고 신규 FAQ·중복 언어 링크 및 discovery import를 제거했다.
- 검색 계약 테스트에서 런타임 확장을 요구하던 단언을 복원된 소개 기준으로 조정했다.
- HTML 메타/정적 소개·FAQ, robots/sitemap, GA4, PWA는 수정하지 않았다. Google 검증 태그와 기존 정책 링크도 보존했다.
- 집중 테스트 2개 통과: 홈페이지 기본 목적/Google 사용 설명 유지, 정적 검색 메타·언어별 HTML 계약 유지. 코드가 추가 변경되지 않아 배포 시 동일 테스트를 반복하지 않는다.
- 사용자가 복원안을 확인하고 커밋·푸시·main 병합·운영 배포를 승인했다. 작업 브랜치 `work/facs-auth-intro-restore`를 보관하고 Git 연동 운영 배포 1회로 반영한다.
- 운영 Vercel 프로젝트 `prj_TO6nO7SfgNp0rzrBpxNDK1DMTrJq`의 도메인 `www.factsmack.com`, Production 브랜치 main, Production Supabase 호스트 `rrcntobfmxlwbbjtlbge.supabase.co`를 다시 확인한다. 배포 후 결과는 복구 태그 주석에 기록하여 문서만을 위한 추가 배포를 피한다.
