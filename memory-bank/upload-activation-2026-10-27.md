# 업로드 활성화 개선 — 2026-10-27

## 승인 범위

- 사용자가 승인한 활성 사용자→첫 게시 전환 개선 1~8번을 기존 업로드·평가·삭제 규칙을 바꾸지 않는 안내형 변경으로 구현한다.
- 새 강제 팝업, 업로드 제한, 자동 게시, 개인정보 수집은 추가하지 않는다.
- 질문·파일명·사진/동영상 URL은 분석 이벤트에 포함하지 않는다.

## 변경

- 운영 기준값: 최근 7일 익명 세션 101, 첫 평가 1, 업로드 완료 1, 공개 게시 1, 평가 1. 최근 30일은 익명 세션 412, 첫 평가 2, 업로드 완료 이벤트 14, 현재 공개 게시 1, 평가 5다. 익명 세션 수는 GA4 사용자 수와 같은 지표가 아니다.
- `upload_opened`, `media_selected`, `publish_attempted`를 기존 익명 퍼널에 추가했다. 서버에는 이벤트명, 임시 세션 UUID, 선택적 게시물 UUID만 허용하며 기존 30일 자동 파기를 그대로 적용한다.
- 첫 게시 전에는 사진 한 장부터 시작하도록 세부 설정을 미디어 선택 뒤에 보여 준다. 기존 최대 5장+동영상 1개, 카테고리, 공개 범위, 질문, 나이 평가, 권리 확인, 게시 규칙은 유지한다.
- 미디어 선택기 아래에 게시 전 비공개, 공개 범위 선택, 언제든 영구 삭제 가능 안내를 한·영으로 추가했다.
- 피드에는 첫 게시용 일일 질문, 이번 방문의 작성 중 초안 복귀, 게시 완료 후 결과 확인 안내를 작은 인라인 카드로 표시한다. 피드·평가·업로드를 가리거나 제한하지 않는다.
- 기존 평가 후 `나도 평가받기` 동작은 유지하고 버튼 식별성만 높였다.
- 운영자 집계 화면에 업로드 열기→미디어 선택→게시 시도→업로드 완료 단계를 추가했다.

## 검증

- 계약 테스트 3건 통과: 허용 이벤트, 집계 전용 SQL, 기존 게시/영구 삭제 보존 문구.
- 프로덕션 Vite 빌드 통과.
- 스테이징 DB에 SQL 적용 성공. 롤백 트랜잭션 안에서 새 이벤트 1건 저장을 확인하고 데이터는 남기지 않았다.
- 로컬 스테이징 브라우저에서 합성 이미지 선택 후 피드 이동→`작성 중인 게시물이 있어요`→`계속 작성`으로 파일이 유지됨을 확인했다. 게시물은 생성하지 않았다.
- 브라우저 네트워크에서 `upload_opened`, `media_selected`가 각각 204였고 요청 본문에 이벤트명·익명 세션 UUID·null 게시물 ID만 포함됨을 확인했다.
- 운영 DB에도 동일 SQL 적용 성공. 롤백 검증에서 새 이벤트 저장 가능성을 확인했고 테스트 데이터는 남기지 않았다.
- 작업 후 Supabase CLI 링크를 스테이징으로 복구하고 대상 가드 통과를 확인했다.

## 별도 운영 위험

- Supabase 대시보드가 이전 결제 주기 무료 할당량 초과와 2026-11-19 제한 가능성을 표시했다. 이 작업에서 요금제·결제·용량 설정은 변경하지 않았다.
