## PRE-05 정식 정책 문구 준비

현재 `LegalPolicyDialog.jsx`의 한·영 문구는 공개 MVP 안내로 적용되어 있으나 정식 법률 검토를 마친 버전은 아니다. 도메인은 이미 누구나 접근 가능하므로 이를 장래 출시 전 준비가 아닌 현행 공개 운영의 우선 보완 항목으로 다룬다. 코드에는 Supabase 인증·미디어 저장, 게시물·평가·댓글·신고·차단·권리 동의, 세션·분석 이벤트 처리가 확인된다. 이 목록은 실제 운영 설정과 법적 고지 범위를 확정했다는 뜻이 아니다.
정책 문서의 미확정 상태는 사용자의 업로드·피드 등록을 차단하는 기능 요구가 아니며, 이 점검표 변경으로 기존 사용자 흐름을 제한하지 않는다.
2026-10-17 현행 안내의 한·영 항목 구조와 주요 사실(운영 주체·문의·연령·콘텐츠 삭제·계정 탈퇴 미지원)을 대조했고, 현재 문구 사이에 수정이 필요한 불일치는 발견하지 못했다. 이는 미결정 보유기간을 채우거나 장래 정식 한국어 원문의 영어 대조를 완료했다는 뜻이 아니다.

### 승인된 신고 기록 보존·파기 경로 (DB 적용 완료, 월별 운영 필요)

- 2026-10-17 승인: 신고 적용·반려로 종결된 건은 최종 처리일부터 1년 경과 후 월별 정기 파기한다. 접수·검토 중 건은 월별로 재검토한다. 월별 파기이므로 실제 삭제일은 1년 경과일보다 최대 한 달가량 늦을 수 있다.
- 로컬 마이그레이션 `202610170001_moderation_retention_purge.sql`은 검토 이력 불변 규칙에 데이터베이스 소유자의 보존 만료 파기만 예외로 두고, 종결된 `reports`와 해당 `moderation_actions`를 함께 삭제한다. 진행 중 건과 별도 보존 표시가 있는 건은 제외한다. 기존 `delete_my_post`·`delete_own_comment` 함수와 피드 등록 흐름은 변경하지 않는다.
- 2026-10-17 스테이징에서 단일 SQL을 적용하고 롤백형 실제 DB 검증으로 2년 경과 신고·감사행 파기, 활성 보류·최근 신고 보존, 불변 트리거의 일반 수정 거부를 확인했다. 운영에서도 같은 SQL을 적용했고 보존 표시 테이블·파기 함수 설치 및 회원 실행 권한 없음, 현재 신고 0건을 확인했다. 작성자 콘텐츠 삭제 코드는 변경하지 않았다.
- 매월 운영자는 미처리 건·별도 보존 사유를 검토하고, 소유자 권한으로 `select public.purge_expired_moderation_reports();`를 결과가 0건일 때까지 실행해 처리 건수를 기록한다. 메일로 접수된 이의·분쟁과 첨부파일의 만료 파기는 DB와 별도로 확인한다. DB의 정기 자동 실행은 아직 설정하지 않았다.
- 스테이징 ref `zvaheyfumpmzrolsbtrf`와 운영 ref `rrcntobfmxlwbbjtlbge`를 각각 가드 검사하고, 공개 도메인 `www.factsmack.com` → Vercel `product-test` Production `VITE_SUPABASE_URL` → Supabase Dashboard `FACt.Smack` ref를 다시 대조했다. 기존 로컬 마이그레이션 전체가 원격 이력 미등록이므로 `db push`는 사용하지 않았다. CLI 연결은 작업 후 스테이징으로 복구했다.
- 한·영 개인정보 안내 변경은 2026-10-17 운영 배포 `7fc4ae9`에 포함됐다. 해당 안내 시행일은 2026-10-17, 이용약관 등 기존 안내 시행일은 2026-10-09다.

운영 DB와 Storage의 실제 삭제가 확인되었다. 2026-10-11 운영 프로젝트 `FACt.Smack`

- Free에는 자동 백업과 PITR가 없다. 사용자 결정(2026-10-14)에 따라 운영 데이터 복구본 생성·보관·격리 복원은 **MVP 출시 이후**로 옮긴다. 출시 전 완료된 안전조치로 표시하지 않으며, 현재 운영 데이터의 복구 공백을 남은 위험으로 명시한다.
- 1주 비활성 일시중지와 짧은 로그 보존으로 장애 원인을 놓칠 수 있으므로 문의에는 발생 시각을 필수로 받는다.
- DB 500MB, 파일 1GB, egress 5GB 한도에 근접하거나 무중단·자동 복구가 필요해지면 `OPS-01` 묶음 작업에서 Pro 전환을 승인한다.
- 플랜 전환, 결제수단 등록, 지출 한도 변경은 별도 사용자 승인 없이 실행하지 않는다.
- 근거: https://supabase.com/pricing, https://supabase.com/docs/guides/platform/backups

### 인증 메일 전달 게이트

- `REL-06`은 완료(승인)다. Resend custom SMTP와 `mail.factsmack.com` 발신 도메인이 연결됐으며, 실제 이메일 OTP 수신·모바일 로그인 흐름도 사용자 점검으로 확인했다.
- 공개 운영에서는 Resend의 일일·시간당 사용량과 bounce를 확인하고, 한도 또는 전달 실패 징후가 있을 때만 원인을 점검한다.
- 제공자 교체, DNS 변경, 유료 플랜 전환은 새 요구가 생기기 전까지 다시 제안하거나 실행하지 않는다.
