## PRE-05 정식 정책 문구 준비

현재 `LegalPolicyDialog.jsx`의 한·영 문구는 Closed Beta 안내 초안이며 정식 고지가 아니다. 도메인은 이미 누구나 접근 가능하므로 이를 장래 출시 전 준비가 아닌 현행 공개 운영의 우선 보완 항목으로 다룬다. 코드에는 Supabase 인증·미디어 저장, 게시물·평가·댓글·신고·차단·권리 동의, 세션·분석 이벤트 처리가 확인된다. 이 목록은 실제 운영 설정과 법적 고지 범위를 확정했다는 뜻이 아니다.

| 결정 항목 | 현재 확인 상태 | 정식 문구 전에 필요한 정보 |
| --- | --- | --- |
| 운영 주체·문의 | 사용자 제공 운영 주체 `tweety and company`, 연락처 `joonkyou.park@gmail.com`을 한·영 안내에 반영하고 승인 | 정식 정책 법률 검토 시 표기·문의 범위 확인 |
| 처리 항목·외부 서비스 | 아래 코드 기반 목록과 운영 Supabase 리전·인증 제공자·SMTP 설정, Vercel 플랜·배포·사용량 확인 | 실제 수집 항목·목적, 외부 서비스 계약·보존·국외 이전 사실 확인 |
| 보존·삭제 | 게시물 `hide_my_post`와 댓글 `delete_own_comment`는 소프트 삭제다. 원본 게시물·미디어·평가 기록의 영구 파기는 확인되지 않았고 계정 탈퇴·자동 파기 흐름도 코드에서 확인되지 않았다. 분석 이벤트에는 만료 기한이 없다. 영구 삭제·탈퇴 기능은 사용자 결정에 따라 공개 MVP 이후 `REL-05`로 이관 | 공개 MVP에서는 실제 처리에 맞는 보존 기준과 요청 접수·처리 방식을 확정하고 정식 정책에 정확히 고지. 영구 삭제·탈퇴 구현 자체는 이 출시 게이트에 포함하지 않음 |
| 미성년자·콘텐츠 | 신고 기준 초안 존재 | 가입 가능 연령과 검토·이의제기·콘텐츠 조치 기준 확정 |
| 검토·게시 | 정식 문구 법률 검토 미완료 | 확정된 한국어 원문 검토 후 영어 문구 대조, 발효일·변경 고지 방식 확정 |

위 사실을 받기 전에는 임의의 기간·사업자·위탁 사실을 만들어 넣거나 초안을 정식 정책으로 표시하지 않는다.

보존·삭제 결정 전에는 화면에서 사라지는 소프트 삭제를 영구 파기로 설명하지 않는다. PRE-05는 공개 MVP에서 실제 운영할 접수·처리·보존 방식의 고지와 검토를 요구하며, `REL-05`의 향후 영구 삭제 기능 완료를 요구하지 않는다.

### 외부 서비스 사실 확인

| 서비스 | 코드에서 확인한 용도 | 운영에서 아직 확인할 사실 |
| --- | --- | --- |
| Supabase | Auth, DB, 미디어 Storage, 자체 퍼널 이벤트 RPC. 2026-10-04 운영 대시보드에서 Free 프로젝트 리전 `ap-northeast-2`(서울) 확인. 2026-10-05 공식 가격표 기준 Free는 DB 500MB, 파일 1GB, egress 5GB, cached egress 5GB, 월간 활성 사용자 50,000명이며 1주 비활성 시 일시중지된다. 자동 백업·PITR·지원 SLA가 없고 API/DB 로그는 1일, Auth 감사 로그는 1시간이다 | 현재 DB·Storage·egress 사용량, 수동 복구본 보관 방식, 처리 위탁·국외 이전의 계약상 사실 확인 |
| Google·Resend | 운영 실기기 OAuth 로그인과 운영 Supabase Google 제공자 활성 확인. 이메일 인증은 Resend custom SMTP(`smtp.resend.com`)와 검증된 발신 도메인 `mail.factsmack.com`을 사용하며, 실제 OTP 수신·로그인 흐름을 사용자 점검으로 확인 | OAuth로 실제 수신되는 항목, Resend 발송·bounce 기록의 처리 관계·보존 |
| Vercel | 승인된 운영 웹 배포·도메인 제공. 2026-10-04 운영 대시보드에서 Hobby 플랜, 최신 운영 배포 `Ready`, 최근 6시간 오류율 0%, 최근 30일 Fast Data Transfer 1.18GB/100GB 확인. 최근 운영 배포 목록에 한도·빌드 차단 신호 없음 | 로그·분석 기능의 실제 사용 범위, 리전·보존 설정 및 처리 위탁 내용 확인. 현재 수치는 여유가 있으나 공개 후 주기적으로 사용량 확인 |
| Kakao | 운영 Supabase 제공자 비활성. 2026-10-04 사용자 결정으로 로그인 화면 버튼을 숨김 | 공개 MVP 이후 제공자 연결·오류 처리·실기기 검증을 완료하기 전에는 인증 제공자로 고지하지 않음 |

위 표는 코드·기존 운영 점검·이번 Supabase 대시보드에서 확인한 범위다. 서울 리전 확인만으로 외부 서비스 계약·전체 데이터 처리 위치·국외 이전 여부를 확정하지 않는다. 나머지 운영 사실을 확인한 뒤 정책 원문에 반영한다.

### REL-02 최소 운영 관측

- 관리자 전용 `get_mvp_operational_metrics(24)`는 최근 24시간의 신규 회원·게시물·평가·댓글·신고 처리와 익명 퍼널 합계, 현재 미처리 신고 수·가장 오래된 접수 시각만 반환한다.
- 개별 회원·게시물·신고·세션 원문은 운영 지표 응답에 포함하지 않는다. 조회 범위는 1~168시간으로 제한한다.
- 브라우저 오류는 DB 숫자로 추정하지 않고 Vercel Runtime Logs의 실제 오류 시각·경로와 사용자 문의를 대조한다.
- 자동 경보 서비스나 임의 임계치는 추가하지 않는다. 공개 초기의 확인 주기와 주의 기준을 운영자가 확정한 뒤 필요한 알림만 별도 승인한다.
- 2026-10-05 사용자 승인 후 운영 Supabase SQL Editor로 함수를 적용했고, 함수 존재와 `anon=false`·`authenticated=true` 실행 권한을 확인했다. 함수 내부의 `admin` 역할 검사와 1~168시간 제한은 저장소 계약 테스트 3개로 확인했다.

### Supabase Free 운영 게이트

- 공개 확대 전 운영 대시보드에서 DB, Storage, egress 사용량을 한 번 기록한다.
- Free에는 자동 백업과 PITR가 없으므로 운영 데이터의 수동 복구본 생성·보관 절차를 정한다.
- 1주 비활성 일시중지와 짧은 로그 보존으로 장애 원인을 놓칠 수 있으므로 문의에는 발생 시각을 필수로 받는다.
- DB 500MB, 파일 1GB, egress 5GB 한도에 근접하거나 무중단·자동 복구가 필요해지면 `OPS-01` 묶음 작업에서 Pro 전환을 승인한다.
- 플랜 전환, 결제수단 등록, 지출 한도 변경은 별도 사용자 승인 없이 실행하지 않는다.
- 근거: https://supabase.com/pricing, https://supabase.com/docs/guides/platform/backups
