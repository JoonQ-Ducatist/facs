필수 확인을 고정한다. 각 행은 실제 증거가 있을 때만 완료로 바꾼다.

이는 새로운 데스크톱/모의 QA 결과가 아니며, 별도의 재검증을 하지 않는다.

합의된 MVP 범위의 출시 전 개발·배포·필수 확인은 완료다. 무료 전송량 초과는
해결 완료로 표시하지 않고 운영 위험으로 이관한다. 홍보 확대 여부를 새 기능
개발·피드 등록 차단·공개 승인 게이트로 사용하지 않는다. 실제 대외 홍보·공지
발송이나 유료 전환은 이번 사용자 확인만으로 실행하지 않는다.

그때도 초과 상태이면 제한될 수 있다는 안내다. 모든 API 정상의 보증은 아니다.
기존 ‘유예 종료일 미확인’ 기록은 과거 관측 결과로만 보존한다.

개인정보 요청은 기존 접수처와 위 표를 그대로 사용한다. 운영자는 접수 시각·요청 유형·
대상 계정·처리 상태만 최소 기록하고, 승인된 **5영업일 이내 확인** 기준에 따라 접수
사실과 추가 확인 필요 여부를 회신한다. 이는 처리 완료 기한이 아니다. 계정 자료의 열람·
정정·삭제처럼 제삼자에게 영향을 줄 수 있는 조치 전에는 등록된 계정 이메일과 요청
회신 주소의 일치 여부를 확인하고, 필요한 경우 등록 주소로 별도 확인 메일을 보낸다.
이메일 일치만으로 모든 권한을 확정하지 않으며 접근권을 잃었거나 주소가 불일치하면
자동 거절·자동 삭제하지 않고 개별 검토한다. 비밀번호·OTP·신분증 원본을 일반 이메일로
요구하지 않는다. 확인 후에는 대상 데이터와 다른 사람의 정보가 섞이는지 점검하고,
가능한 처리 범위·제한 사유·결과를 같은 공식 채널로 회신한다. 운영 DB의 직접 삭제나
기록 파기는 별도 대상 확인과 승인 없이 실행하지 않는다. 이는 내부 운영 초안이며
법률상 처리 기한·본인확인 요건을 확정한 문구가 아니다.

### REL-02 최소 운영 관측

- 관리자 전용 `get_mvp_operational_metrics(24)`는 최근 24시간의 신규 회원·게시물·평가·댓글·신고 처리와 익명 퍼널 합계, 현재 미처리 신고 수·가장 오래된 접수 시각만 반환한다.
- 개별 회원·게시물·신고·세션 원문은 운영 지표 응답에 포함하지 않는다. 조회 범위는 1~168시간으로 제한한다.
- 브라우저 오류는 DB 숫자로 추정하지 않고 Vercel Runtime Logs의 실제 오류 시각·경로와 사용자 문의를 대조한다.
- 자동 경보 서비스나 임의 임계치는 추가하지 않는다. 출시 후 첫 7일은 하루 2회, 이후 하루 1회 운영 지표·오류·문의 상태를 확인하고, 장애 문의가 접수되면 추가 확인한다.
- 2026-10-05 사용자 승인 후 운영 Supabase SQL Editor로 함수를 적용했고, 함수 존재와 `anon=false`·`authenticated=true` 실행 권한을 확인했다. 함수 내부의 `admin` 역할 검사와 1~168시간 제한은 저장소 계약 테스트 3개로 확인했다.

### Supabase Free 운영 게이트

- 공개 확대 전 운영 대시보드에서 DB, Storage, egress 사용량을 한 번 기록한다.
- 2026-10-11 운영 프로젝트 `FACt.Smack`(ref `rrcntobfmxlwbbjtlbge`)로 필터해 읽기 전용 확인: 현 청구 주기(2026-10-05~11-05)에 DB 28.16MB/500MB, Storage 0.222GB/1GB, egress 0.049GB/5GB, cached egress 0.015GB/5GB, MAU 1/50,000, Realtime peak 2/200이다. 한도 초과·제한 징후는 없다. 수치는 최대 1시간 지연될 수 있으므로 다음 운영 배포 묶음 직전에 다시 기록한다.
- 2026-10-17 같은 주기의 **조직 합산** cached egress는 5.24GB/5GB로 초과했다. 프로젝트별로 스테이징 `facs-rls-test` 5.22GB, 운영 `FACt.Smack` 0.02GB다. 사용량 그래프의 큰 증가분은 10월 5일·11일에 집중됐고, 현재 스테이징 Storage 객체 크기 합계는 약 54MB다. 반복 QA 요청의 영향 가능성은 있으나 원본 요청 로그로 인과관계를 확인하지 못했다. 피드 코드에는 대화형 동영상마다 화면의 `<video>`와 별도의 포스터 캡처용 `<video>`가 같은 URL을 요청할 수 있는 경로가 있다. 원인 미확정 상태에서 피드·업로드 제한, 요금제 전환, 운영 설정 변경은 하지 않는다. 이번 초과분은 이미 발생한 전송량이므로 현재 주기 안에서 되돌릴 수 없고, 추가 미디어 반복 QA를 멈춘 뒤 다음 주기 추세를 한 번 확인한다.
- 2026-10-18 공개 확대 전 읽기 전용 재확인: 같은 청구 주기(10월 5일~11월 5일) 조직 합산 cached egress는 5.24/5GB(105%)이며, 이 중 스테이징 `facs-rls-test` 5.221GB, 운영 `FACt.Smack` 0.019GB다. 운영만 필터하면 일반 egress 0.117GB, Storage 0.223GB, DB 28.43MB, MAU 2다. 조직 합산 일반 egress는 3.086/5GB(62%), Storage는 0.278/1GB(28%)다. 필터 값은 조직 합산 한도를 대체하지 않으며 수치는 최대 1시간 지연될 수 있다. 서비스 제한이 이미 발생했다는 증거는 없지만, 무료 한도 초과 배너가 있으므로 공개 확대 전 유예·제한 상태를 재확인한다. 별도 부하 QA·피드 제한·유료 전환은 하지 않았다.
- Supabase 공식 안내에 따르면 Free 한도 초과 시 알림과 유예기간을 거치며, 계속 초과하면 서비스 제한이 적용될 수 있다. 이미 전송된 양은 현재 청구 주기에서 줄일 수 없고 다음 주기 시작 때 누적량이 초기화된다. 따라서 현재 배너만으로 운영 API가 이미 제한됐다고 단정하지 않되, 공개 확대 전 402 `exceed_egress_quota` 응답 여부를 관련 장애 증거가 있을 때 확인한다. https://supabase.com/docs/guides/platform/manage-your-usage/egress · https://supabase.com/docs/guides/troubleshooting/http-status-codes
- Free에는 자동 백업과 PITR가 없다. 사용자 결정(2026-10-14)에 따라 운영 데이터 복구본 생성·보관·격리 복원은 **MVP 출시 이후**로 옮긴다. 출시 전 완료된 안전조치로 표시하지 않으며, 현재 운영 데이터의 복구 공백을 남은 위험으로 명시한다.
- 1주 비활성 일시중지와 짧은 로그 보존으로 장애 원인을 놓칠 수 있으므로 문의에는 발생 시각을 필수로 받는다.
- DB 500MB, 파일 1GB, egress 5GB 한도에 근접하거나 무중단·자동 복구가 필요해지면 `OPS-01` 묶음 작업에서 Pro 전환을 승인한다.
- 플랜 전환, 결제수단 등록, 지출 한도 변경은 별도 사용자 승인 없이 실행하지 않는다.
- 근거: https://supabase.com/pricing, https://supabase.com/docs/guides/platform/backups
